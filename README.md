# Тестирование поля «Лимит расходов»

**Контекст по скриншоту:** модалка выпуска, поле суммы в $, рядом селект «Тип лимита» (Без лимита / День / Неделя / Месяц / Лайфтайм), кнопки «Отменить» и «Выпустить».

Спеки нет, поэтому фиксирую допущения и проверяю их как кейсы: валюта - доллары с точностью до цента, минимальный лимит 0.01, максимум явно не задан.

## 1. Позитивные значения

| Ввожу | Что проверяю |
|---|---|
| `1` | минимальное целое |
| `100` | обычное значение |
| `0.01` | минимально возможная сумма в центах |
| `10.50` | дробное с двумя знаками |
| `100.00` | дробное с нулями после точки |
| `999999999` | большое значение, ищу верхнюю границу |

## 2. Границы и точность

| Ввожу | Что проверяю |
|---|---|
| `0` | ноль: это «нет лимита» или ошибка? Если принимается - чем отличается от типа «Без лимита»? |
| `0.001`, `10.505` | больше двух знаков после точки: обрезается, округляется или ошибка? Если округляется - в какую сторону (10.505 → 10.50 или 10.51)? |
| `0.1` | один знак после точки: нормализуется в 0.10? |
| `2147483647` / `2147483648` | граница int32 |
| `9999999999999999` | переполнение, потеря точности float |
| `007` | ведущие нули: нормализуются в 7? |

## 3. Невалидный ввод

| Ввожу | Что проверяю |
|---|---|
| пустое поле + тип «День» → «Выпустить» | обязательность поля, валидация |
| `-100` | отрицательное |
| `abc`, `тест` | буквы латиницей и кириллицей |
| `12a34` | смешанный ввод |
| `1.2.3` | две точки |
| `10,50` | запятая вместо точки: принимается как 10.50 или ошибка? Важно для RU-локали |
| `1 000`, `" 100 "` | пробелы внутри и по краям |
| `$100` | вставка со знаком валюты |
| `1,000.00` | форматированное число из буфера |
| `1e5`, `+100`, `Infinity`, `NaN` | экзотические числовые формы |
| `!@#%`, эмодзи | спецсимволы |
| строка из 1000 символов | maxlength на фронте и отказ бэка |

## 4. Связка с «Тип лимита»

- Тип **«Без лимита»**: поле суммы должно блокироваться или очищаться. Если ввести `100` и переключить на «Без лимита» - что уйдёт на бэк?
- Ввести `100` при типе «День», переключить на «Неделя» - значение сохраняется?
- Переключить «День» → «Без лимита» → «Месяц» - значение восстановилось или сбросилось?
- «Лайфтайм» - есть ли отдельные ограничения на сумму?

## 5. Поведение формы

- «Отменить» после ввода `100`, повторное открытие модалки - поле чистое?
- Двойной клик по «Выпустить» с валидным значением - не создаются ли две сущности
- Esc / клик мимо модалки с введённым значением
- Вставка из буфера (Ctrl+V) и drag-and-drop текста в поле
- Ввод с numpad и с обычной клавиатуры (точка vs запятая на numpad)

## 6. UI/UX

- Плейсхолдер `$` - это подсказка или значение?
- Длинное значение `999999999.99` - не ломает вёрстку поля?
- Мобильный: открывается числовая клавиатура (inputmode)?
- Копирование значения из поля

## 7. API-уровень

Валидация не должна жить только на фронте. Повторяю ключевые негативные кейсы запросом в обход UI:

- `limit = -100`, `0`, `"abc"`, `null`, `1e308`
- `limit` строкой: `"100"`
- отсутствие поля `limit` при типе «День»
- `limit = 100` при типе «Без лимита»

Ожидаю `400` с понятной ошибкой, а не `500` и не создание сущности.

Безопасность: `<script>alert(1)</script>`, `' OR 1=1` - проверяю, что значение экранируется и не исполняется там, где лимит потом отображается.

## 8. После сохранения

- Выпустить с лимитом `10.50` и проверить отображение в списке (формат, валюта, округление)
- Редактирование: сохранённое значение корректно открывается в поле?

## Автотесты

Ключевые кейсы из разделов 1-4 и 7 автоматизированы: [autotests/](autotests/) - API-тесты на pytest. Реального приложения нет, поэтому рядом лежит мок-сервис на FastAPI, реализующий допущения выше, - тесты запускаются одной командой:

```bash
cd autotests
pip install -r requirements.txt
pytest -v
```

43 теста: позитив с нормализацией значений, границы и точность, невалидный ввод (включая типы, инъекции, переполнение), связка лимита с типом, проверка сохранённого значения.
